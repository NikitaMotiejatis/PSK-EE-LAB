Optimistic locking demo

Simulates: User B loads a player, User A commits an update, then User B tries to save its stale snapshot. The merge throws OptimisticLockException; the demo then performs proper recovery in a fresh transaction.

Lab questions

  • (a) What happens to the current transaction when an OLE is thrown? The JTA transaction is marked for rollback (Status.STATUS_MARKED_ROLLBACK). It cannot be committed; the container will roll it back when the @Transactional method exits.
  • (b) What happens to the current EntityManager? How do you save after an OLE? The persistence context is in an undefined state and should not be reused. To save the entity, get a fresh EntityManager (or call em.clear() on a request-scoped one), start a new transaction, re-fetch the entity (its version will match the DB), re-apply the user's intended change, then commit.
